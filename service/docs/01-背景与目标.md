# 01 · 背景与目标

## 1. 需求演进

```
2026-11  阶段一：研究报告
        输入：申万行业成分/权重 + baostock 行情
        输出：42 页 PDF、Excel 数据表、32 张 PNG、155 只龙头的月度序列

2026-11  阶段二：本地服务（本文档描述的对象）
        把「静态报告」变成「可查询、可增量更新、可维护」的 Web 服务
        约束：本地运行、端口 3999、数据先落本地文件、后期换 MySQL
```

## 2. 原始需求拆解

| 需求原文 | 落地方式 | 状态 |
|---|---|---|
| 前后端分离 | FastAPI（3999） + React/Vite（开发 5173，生产由 3999 托管） | ✅ |
| 后端可查询 | 12 个 REST 接口，覆盖行业、龙头、月度序列、总览、导出 | ✅ |
| 后端可维护数据 | `PUT /api/admin/stocks/{code}` 改权重/排序；`GET /api/admin/quality` 体检；`POST /api/sync` 手动同步 | ⚠️ 接口有，前端页面待做（P5） |
| 前端展示股价折线图 | ECharts 多折线，支持绝对价格/归一化切换、下钻、指标表 | ✅ |
| 数据暂放本地文件 | SQLite 单文件 `service/data/astock.db`（5,616 行） | ✅ |
| 后期替换 MySQL | 同一套 SQLAlchemy 表定义 + 双方言 upsert + `ASTOCK_DATABASE_URL` + compose 文件 | ✅ 代码就绪，未实际切换（P6） |
| 端口 3999 | `127.0.0.1:3999`，单端口同时提供 API 与页面 | ✅ |
| 页面刷新拉取上次→本次新增 | `/api/data/version` 判水位 → 需刷新则异步 `POST /api/sync` → 轮询 → 只并入新增月份 | ✅ |

## 3. 范围与非目标

**在范围内**

- 31 个申万一级行业、每行业权重前五、2024-01 起的月度股价
- 查询类接口 + 同步类接口 + 最小维护接口
- SQLite 存储与 MySQL 可切换
- 本地单机运行（127.0.0.1），无公网暴露

**明确不在范围内（当前版本）**

- 用户体系、权限管理、多租户（只有本地 admin token）
- 实时行情/分时/K 线（只有日线与月度聚合）
- 回测、选股、因子计算、组合管理
- 概念板块（AI 算力、机器人等）维度
- 部署到服务器、HTTPS、反向代理、容器化整包
- 移动端专门适配（当前为响应式，非独立 App）

## 4. 用户与使用场景

| 角色 | 场景 | 用到的功能 |
|---|---|---|
| 研究者 | 看某行业龙头历史走势、比较强弱 | 总览页 → 行业详情 → 切换归一化 |
| 数据维护者 | 修正龙头权重、补数据、查同步失败原因 | `/api/admin/*`、`/api/sync/logs`（前端页面待做） |
| 开发者 | 换库、加指标、加页面 | `repo.py`、`analytics.py`、`docs/06` |

## 5. 验收标准（v0.2）

1. `.\start.ps1` 一条命令启动，浏览器打开 `http://127.0.0.1:3999`。
2. 首页展示 31 个行业、155 只龙头、同期沪深 300 涨幅；柱状图可点击下钻。
3. 行业页展示 5 条月度折线，可切换「绝对价格 / 归一化」，可叠加沪深 300（归一化模式）。
4. 指标表包含：权重、基期价、最新价、区间涨跌、年化收益、最大回撤、年化波动、最佳/最差月。
5. `/api/data/version` 返回水位线；有新交易日时刷新页面能自动补数（实测 156 只 / 35 秒）。
6. `/docs` 可用，12 个接口均可调通。
7. 数据与上一阶段报告口径一致（同一股票、同一月份收盘价相同）。

## 6. 关键约束

- **单机**：服务只绑定 `127.0.0.1`，不要直接改成 `0.0.0.0` 暴露到局域网/公网。
- **数据量小**：5,616 行 / 0.4 MB，暂不需要分页、缓存、异步 DB。
- **上游不稳定**：baostock 偶发断连、申万接口可能改版，同步逻辑必须能失败降级。
- **前复权漂移**：任何增量方案都必须处理历史重算问题（见 `00-项目记忆.md` §6）。
