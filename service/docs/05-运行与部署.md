# 05 · 运行与部署

## 1. 环境要求

| 项 | 版本 | 说明 |
|---|---|---|
| 操作系统 | Windows 10/11（已在 Win10 19045 验证） | 也可以跑 Linux/macOS，脚本已兼容 |
| Shell | **Git Bash**（`C:\Program Files\Git\bin\bash.exe`） | `C:\Windows\System32\bash.exe` 是 WSL 转发，本机 WSL 不可用，别用它 |
| Python | 3.11+（本机 3.13.2） | 依赖已 vendor，无需联网安装 |
| Node.js | 18+（本机 26.13.1） | 仅构建前端时需要；日常运行不需要 |
| npm | 9+（本机 11.20.0） | 同上 |
| 浏览器 | Chrome / Edge | ECharts 需要现代浏览器 |
| 磁盘 | 约 200 MB（依赖 + node_modules） | 数据文件 < 1 MB |

## 2. 首次启动

```bash
cd /d/deepseek/astock_sectors/service
./start.sh
```

> 在 **Git Bash** 里执行。若在 PowerShell/cmd 里敲 `bash start.sh`，`bash` 会解析到
> `C:\Windows\System32\bash.exe`（WSL 转发，本机不可用），请改用完整路径：
> `"C:\Program Files\Git\bin\bash.exe" start.sh`。
> 脚本是 LF 换行（`.gitattributes` 强制 `*.sh eol=lf`），避免 Git Bash 报 `$'\r': command not found`。

脚本做的事：

1. 探测 `http://127.0.0.1:3999/api/health`：已运行则直接打开浏览器并退出（不会重复启动）。
2. 检查 `frontend/dist/index.html`，不存在则 `npm install && npm run build`（首次约 1~2 分钟）。
3. 检查 3999 端口是否被其他程序占用，占用则报错退出并列出 PID。
4. 后台启动 `python run.py`，日志追加到 `data/service.log`。
5. 轮询 `/api/health`（最长 90 秒；冷启动首次 import pandas/baostock 可能十几秒），就绪后自动打开浏览器。
6. 前台等待；`Ctrl+C` 或关闭终端会连带停掉后端（原 PS 版是隐藏子进程，可能残留）。

启动后：

- 页面：<http://127.0.0.1:3999>
- API 文档：<http://127.0.0.1:3999/docs>
- 健康检查：<http://127.0.0.1:3999/api/health>

## 3. 日常命令

| 目的 | 命令 |
|---|---|
| 启动（推荐） | `./start.sh` |
| 停止 | `./stop.sh`（可重复执行；`--dry-run` 只看不杀；`--force` 强杀） |
| 仅后端（前台，看日志） | `cd backend && python run.py` |
| 后端热重载（开发） | `cd backend && python run.py --reload` |
| 前端热更新（开发） | `cd frontend && npm run dev`（<http://127.0.0.1:5173>） |
| 重新构建前端 | `cd frontend && npm run build` |
| 初始化/重置数据 | `cd backend && PYTHONPATH=".;./vendor;../../vendor" python -m app.seed` |
| 清理缓存（可重复执行） | `../clean.sh`（预览：`../clean.sh --dry-run`） |
| 换端口 | `ASTOCK_PORT=4000 ./start.sh` / `ASTOCK_PORT=4000 ./stop.sh` |
| 查看端口占用 | `./stop.sh --dry-run` |

> `python -m app.seed` 必须在 `backend` 目录下执行，且 `PYTHONPATH` 要包含 `vendor` 与上一级的 `vendor`（baostock 在那里）。

## 4. 环境变量

复制 `.env.example` 为 `.env` 后修改即可生效（`config.py` 启动时自动加载，且**不覆盖**已存在的进程环境变量）。
配置优先级：**进程环境变量 > `service/.env` > 代码默认值**。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `ASTOCK_HOST` | `127.0.0.1` | 监听地址；不要改成 `0.0.0.0` 对外暴露 |
| `ASTOCK_PORT` | `3999` | 服务端口 |
| `ASTOCK_DATABASE_URL` | `sqlite:///.../data/astock.db` | 阶段二换成 `mysql+pymysql://...` |
| `ASTOCK_DATA_DIR` | `service/data` | SQLite 文件目录 |
| `ASTOCK_BASE_MONTH` | `2023-12` | 归一化基期 |
| `ASTOCK_SEED_FROM` | `2023-12-01` | 全量同步起点 |
| `ASTOCK_HISTORY_START` | `2024-01` | 查询默认起始月份 |
| `ASTOCK_ADMIN_TOKEN` | `local-dev-token` | 维护接口令牌 |
| `ASTOCK_CORS_ORIGINS` | `http://127.0.0.1:5173,http://localhost:5173` | 开发态跨域白名单 |

## 5. 目录与关键文件

| 路径 | 作用 | 是否可删 |
|---|---|---|
| `backend/app/` | 后端源码 | 否 |
| `backend/vendor/` | Python 依赖 | 否（删了要重装） |
| `backend/run.py` | 启动入口（注入 vendor 路径） | 否 |
| `frontend/src/` | 前端源码 | 否 |
| `frontend/dist/` | 构建产物 | 可删，删后需重新 build |
| `frontend/node_modules/` | 前端依赖 | 可删，重装需联网 |
| `data/astock.db` | 数据库 | 可删，删后 seed 重建 |
| `data/astock.db-wal` / `-shm` | SQLite WAL 文件 | 随主库 |
| `docs/` | 文档 | 否 |

## 6. 日志

- 服务日志：`start.sh` 把 `python run.py` 的输出追加到 `service/data/service.log`（每次启动写一行时间戳）。
- 实时跟踪：`tail -f data/service.log`
- 纯前台启动：`cd backend && python run.py`
- 同步日志：数据库 `sync_log` 表 + `GET /api/sync/logs`。
- 业务异常不会写文件，只在响应里返回 `detail`。

## 7. 备份与恢复

SQLite 是单文件，备份 = 复制文件（先停服务，避免 WAL 未合并）：

```bash
./stop.sh                      # 先停服务，避免 WAL 未合并
mkdir -p data/backup
cp data/astock.db "data/backup/astock-$(date +%Y%m%d).db"
```

恢复：停服务 → 覆盖 `astock.db` → 启动。

> 不要只复制 `astock.db` 而漏掉 `-wal`：若服务在运行中复制，可能拿到不一致快照。

## 9. 开机自启（可选）

推荐用「任务计划程序」直接跑后端（不依赖 Git Bash）：

| 项 | 值 |
|---|---|
| 触发器 | 登录时 |
| 程序 | `python` |
| 参数 | `run.py` |
| 起始于 | `D:\deepseek\astock_sectors\service\backend` |

之后手动 `./start.sh` 打开页面、`./stop.sh` 停止即可。

> 不建议计划任务跑 `start.sh`：它在前台等待服务退出，且依赖 Git Bash 的 PATH。
> 若坚持用，命令写 `"C:\Program Files\Git\bin\bash.exe" -lc "./start.sh --no-browser"`
> （登录 shell 会自动加载 `~/.bash_profile`）。

## 10. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `端口 3999 已被占用` | 上一次服务没退干净 | `./stop.sh`（先 `--dry-run` 看），或改 `ASTOCK_PORT` |
| 页面 404 / 空白 | `frontend/dist` 不存在或构建失败 | `cd frontend && npm run build`；看构建报错 |
| 页面提示「前端尚未构建」 | 后端启动时 dist 不存在 | 同上，构建后重启后端 |
| `ModuleNotFoundError: fastapi` | 没用 `run.py` 启动，或 vendor 被删 | 用 `python run.py`；或重跑 `vendor_backend2.py` |
| 同步一直 `running` | baostock 网络慢/断连 | 看 `sync_log.message`；等 3 次重试结束；再手动点一次 |
| 同步 `failed`，提示 baostock | 上游登录失败 | 重试；检查网络能否访问 baostock |
| 页面数据不更新 | 非交易日 / 未到 15:05 | 正常；`/api/data/version` 看 `needsRefresh` |
| 某只股票图表断线 | 停牌或缺月 | `/api/admin/quality` 查 `missing_month`；补数据或接受断点 |
| `$'\r': command not found` | `.sh` 被 CRLF 检出 | `dos2unix start.sh`，或重新 `git checkout`（已加 `.gitattributes` 强制 LF） |
| `NtCreateDirectoryObject ... 0xC0000022` | 用了 WSL 的 `System32\bash.exe`，或 DSH 沙箱未放开 | 换 Git Bash；DSH 里需 `danger-full-access` |
| `start.sh` 一直不返回 | 正常：前台等待服务运行 | 另开终端 `./stop.sh`，或 Ctrl+C |
| `npm` 报 `spawn EPERM` | 沙箱/权限限制 | 在普通终端运行；DSH 里需 `danger-full-access` |
| 中文乱码（终端） | 终端不是 UTF-8 | 接口与日志都是 UTF-8；用支持 UTF-8 的终端或看浏览器 |
