## 4. 推送前检查清单

```powershell
cd D:\deepseek\astock_sectors

# 1) 敏感信息复扫（0 高危才继续）
python service\docs\_secret_scan.py

# 2) 初始化仓库，先干跑看会提交什么
git init
git add -n .
#   确认清单里没有：service/backend/vendor、node_modules、*.db、.env、archive/system-acl

# 3) 验证关键忽略规则
git check-ignore -v service\data\astock.db service\frontend\node_modules service\backend\vendor
#   预期输出对应 .gitignore 行号；无输出说明没被忽略

# 4) 真正提交
git add .
git status --short
git commit -m "feat: A股行业龙头股月度行情服务 v0.2.2 + 研究报告"

# 5) 关联远程并推送（替换成你的仓库地址）
git branch -M main
git remote add origin https://github.com/<your-name>/<repo>.git
git push -u origin main
```

推送后建议在 GitHub 仓库设置里开启：

- **Secret scanning** 与 **Push protection**（防止以后误提交 token）；
- 若仓库公开，确认 `交付/` 是否有版权/数据再分发限制（申万行业分类与 baostock 数据请遵守各自条款）。

## 5. 体积与 Git LFS（可选）

当前约 231 MB，其中被忽略的依赖占大头（不会进 git）；**实际入库约 25~30 MB**（代码 + 文档 + `交付/`）。
`交付/` 的 PDF/DOCX/XLSX/PNG 共约 24 MB，直接提交会让仓库永久变大。二选一：

```powershell
# 方案 A：只提交说明，交付物传到 GitHub Release
#   把 交付/ 加入 .gitignore，或手动不 add

# 方案 B：用 Git LFS 跟踪大文件
git lfs install
git lfs track "交付/**"
git add .gitattributes
```

推送后可用 `git count-objects -vH` 查看仓库体积。

## 6. 可选：脱敏绝对路径

如果不想公开本机目录结构，可在项目根执行（会改动文档与脚本里的示例路径）：

```powershell
Get-ChildItem -Recurse -File -Include *.md,*.py,*.ps1,*.cmd |
  Where-Object { $_.FullName -notmatch 'node_modules|\\vendor\\' } |
  ForEach-Object {
    $c = [IO.File]::ReadAllText($_.FullName, [Text.UTF8Encoding]::new($false))
    $c = $c.Replace('D:\deepseek\astock_sectors', '<repo>')
    [IO.File]::WriteAllText($_.FullName, $c, [Text.UTF8Encoding]::new($false))
  }
```

> 注意：`AGENTS.md` 与 README 里的 `cd` 命令会变成 `cd <repo>\service`，本地使用时需手动替换回来。
> 更稳妥的做法是保留路径（不含用户名），仅在 README 注明「示例路径，按实际位置调整」。

## 7. 复扫与维护

- 每次新增配置/脚本后，运行 `python service/docs/_secret_scan.py`，保持「高危 0」。
- 新增环境变量时，只写进 `.env.example`，不要写实体 `.env`。
- 数据库、日志、依赖目录永远不要 `git add -f`。
- 若将来接入真实账号体系，把 `local-dev-token` 从代码默认值中移除（改为启动时强制要求环境变量）。
