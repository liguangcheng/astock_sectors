# 06 · 开发指南

## 1. 代码地图

```
backend/
├─ run.py                 启动入口：注入 vendor 路径 → uvicorn.run
├─ app/
│  ├─ config.py           所有可配置项（端口/DB/口径/容差）
│  ├─ db.py               engine + 5 张表 + init_db()
│  ├─ repo.py             仓储层：唯一数据出口，方言适配
│  ├─ analytics.py        纯函数：to_monthly / metrics / group_by_code / month_range
│  ├─ seed.py             种子导入 CLI
│  ├─ sync_service.py     增量同步（水位线/单飞/复权校验/job 状态）
│  ├─ api.py              12 个 REST 接口
│  └─ main.py             FastAPI 装配 + 静态托管 + SPA 回退
frontend/src/
├─ main.tsx               React 挂载
├─ App.tsx                hash 路由 + 全局同步状态 + 顶栏/页脚
├─ api.ts                 fetch 封装（唯一网络出口）
├─ types.ts               与后端响应对应的类型
├─ styles.css             全站样式（无 UI 框架）
├─ pages/Overview.tsx     总览
├─ pages/Industry.tsx     行业详情
└─ components/
   ├─ LineChart.tsx       折线（ECharts）
   └─ OverviewBar.tsx     柱状（ECharts）
```

**依赖方向**：`api → analytics / repo`；`repo → db`；`sync_service → repo + baostock`；`main → api`。
`analytics` 不依赖任何 IO，最容易写单测。

## 2. 常见改造任务

### 2.1 新增一个查询接口

以「按月份返回全市场涨跌统计」为例：

1. **仓储**：如需要新查询，在 `repo.py` 加方法（返回 `list[dict]`）。
2. **分析**：纯计算放 `analytics.py`。
3. **接口**：在 `api.py` 加路由：

```python
@router.get("/stats/monthly")
def monthly_stats(start: str = Query(HISTORY_START)):
    rows = repo.prices_for([s["code"] for s in repo.list_stocks()])
    monthly = {c: analytics.to_monthly(v) for c, v in analytics.group_by_code(rows).items()}
    return {"start": start, "items": [...]}
```

4. **前端**：`api.ts` 加方法 + `types.ts` 加类型 + 页面调用。
5. **文档**：更新 `docs/04-接口文档.md` 与 `docs/09-变更日志.md`。

> 不要在 `api.py` 里直接 `engine.connect()`；也不要 import baostock。

### 2.2 新增一个页面

1. `src/pages/Xxx.tsx`，从 `api.ts` 取数，套用现有 `.card` / `.kpis` 样式。
2. `App.tsx` 的 `parseHash()` 增加路由（如 `#/quality`），并在渲染分支加一行。
3. 顶栏加导航入口（如有必要）。
4. `npm run build`，刷新 3999 验证。

### 2.3 修改指标口径

以「增加卡玛比率」为例：

1. `analytics.metrics()` 里计算 `calmar = cagr / abs(mdd)`，加进返回字典。
2. 前端 `types.ts` 的 `Metrics` 加字段，`Industry.tsx` 表格加一列（注意表格已 11 列，考虑横向滚动）。
3. 文档：`docs/00` 的「数据口径」表 + `docs/04` 的响应示例。
4. 如果影响历史数字，重跑一次页面并抽查 2~3 只股票与报告对齐。

### 2.4 增加/替换一只龙头

- **临时**：`PUT /api/admin/stocks/{code}` 改 `weight/rank`（只改单只）。
- **永久**：改种子数据源 `../data/selection.json`，然后重跑 `python -m app.seed`（会覆盖同 code 记录）。
- 新增股票（不在 stock 表）：先 `repo.upsert_stocks([...])` 或直接改 seed，再补价格（同步会自动抓）。

### 2.5 增加一个行业

1. `../data/selection.json` 增加行业条目（含 `name/count/stocks`）。
2. `../data/bs_month.json` 增加该行业 5 只股票与（可选）基准的月度收盘。
3. 重跑 seed；前端自动出现新卡片（无硬编码行业列表）。

### 2.6 切换 MySQL（P6）

```powershell

# 3) 指向 MySQL

# 4) 建表 + 导入（create_all 会自动建 5 张表）

# 5) 启动验证

```

**验收清单**：

| 检查 | 期望 |
|---|---|
| `SELECT COUNT(*) FROM industry` | 31 |
| `SELECT COUNT(*) FROM stock` | 155 |
| `SELECT COUNT(*) FROM price_daily` | 5616 |
| 茅台 2026-11-13 收盘 | `1435.26` |
| `/api/industries/801120` 的 `avgCumReturn` | `-12.3` 左右（与 SQLite 一致） |
| 页面总览、详情 | 与 SQLite 版本无差异 |

**已知注意点**：

- MySQL 需要 `utf8mb4`，否则中文乱码；连接串带 `?charset=utf8mb4`。
- 首次建表有外键（stock → industry），`seed` 必须先写行业再写股票（现有实现已保证）。
- 浮点用 `FLOAT` 精度 4 字节；若要精确到分，把 `db.py` 的 `Float` 改 `Double`。
- 切回 SQLite：清空 `ASTOCK_DATABASE_URL` 或设回 `sqlite:///...`。

## 3. 编码约定

| 项 | 约定 |
|---|---|
| Python | 3.11+ 语法（`X | None`），类型标注，文件头 `# -*- coding: utf-8 -*-` |
| 命名 | 表/字段 snake_case；API 路径 kebab/单词；前端组件 PascalCase |
| 金额/涨跌 | 涨跌统一用「百分数数值」（`-8.49`），不要传小数比率 |
| 时间 | 服务端统一 `Asia/Shanghai`；DB 存字符串日期，避免时区转换 |
| 错误 | 业务错误抛 `HTTPException(status, "中文说明")`，不要返回 200 + error 字段 |
| SQL | 只用 SQLAlchemy 表达式，不拼字符串 |
| 前端 | 不用 UI 框架；样式集中在 `styles.css`；网络请求只经过 `api.ts` |
| 注释 | 解释「为什么」，不解释「是什么」 |

## 5. 测试现状与建议

当前**没有自动化测试**。建议按优先级补：

1. `analytics.to_monthly / metrics` 的单元测试（纯函数，最容易）：给定 3 个月日线，断言 `cum_return/mdd/vol`。
2. `repo.upsert_prices` 幂等性测试：同一行插两次，行数不变。
3. API 冒烟测试：`TestClient(app)` 调 `/api/health`、`/api/overview`、`/api/industries/801770`，断言 200 与关键字段。
4. 同步逻辑用 monkeypatch 替换 `_query`，断言重叠校验分支（一致/漂移）。

运行方式（建议）：

```powershell
cd backend
$env:PYTHONPATH=".;.\vendor;..\..\vendor"
python -m pytest -q        # 需先把 pytest 加进 vendor
```

## 6. 性能与扩展提示

- 单行业查询每次都会重算 6 只股票的全部历史；若股票数扩到 500+，建议加 60 秒内存缓存（键：`lastTradeDate + codes`）。
- 首页 `/api/overview` 会遍历 155 只股票，耗时 < 300 ms；若扩到全市场（5000 只），需要改为只查 `is_leader` 且预计算。
- 同步目前串行；若要提速，可改为 4 线程，但 baostock 对并发不友好，需限速并重试。
- 前端 bundle 1.19 MB（gzip 393 KB），主要来自 ECharts；可按需引入 `echarts/core` 减到 ~300 KB。
