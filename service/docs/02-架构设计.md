# 02 · 架构设计

## 1. 总体架构

```
┌─────────────────────────────────────────────────────────────────┐
│ 浏览器（Chrome / Edge）                                          │
│  React 18 + TypeScript + Vite + ECharts                          │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────┐   │
│  │ 总览页        │  │ 行业详情页    │  │ 同步状态条 / 数据截止  │   │
│  └──────┬───────┘  └──────┬───────┘  └──────────┬───────────┘   │
│         └─────────────────┼─────────────────────┘               │
│                     fetch /api/*（同源，无 CORS 问题）            │
└───────────────────────────┼─────────────────────────────────────┘
                            │ HTTP (127.0.0.1:3999)
┌───────────────────────────▼─────────────────────────────────────┐
│ FastAPI 应用（uvicorn，单进程）                                   │
│                                                                  │
│  main.py      应用装配：CORS、静态资源、SPA 回退、启动钩子          │
│  api.py       12 个 REST 接口（参数校验、响应组装）                 │
│  analytics.py 纯函数：月末聚合、收益/回撤/波动、归一化              │
│  repo.py      仓储层：唯一的数据读写出口（SQLAlchemy Core）         │
│  db.py        引擎 + 5 张表定义（SQLite / MySQL 通用）              │
│  sync_service.py  增量同步：单飞锁 + 后台线程 + baostock + 复权校验  │
│  seed.py      种子导入 CLI（复用上一阶段 JSON）                     │
└──────────┬───────────────────────────────────┬───────────────────┘
           │ SQLAlchemy                        │ socket（仅同步时）
┌──────────▼──────────┐              ┌─────────▼──────────────────┐
│ SQLite              │              │ baostock 行情服务           │
│ service/data/        │              │ 前复权日线（adjustflag=2）  │
│ astock.db           │              │ 指数不复权（adjustflag=3）  │
│ 5 张表 / 5,616 行    │              └────────────────────────────┘
└─────────────────────┘
           ▲
           │ 首次/重置
┌──────────┴──────────┐
│ data/*.json（上一阶段）│  selection.json / bs_month.json
└─────────────────────┘
```

生产形态只有一个端口：**3999** 同时提供 `/api/*` 与前端静态文件。
开发形态两个端口：后端 3999，前端 5173（Vite dev server 把 `/api` 代理到 3999）。

## 2. 分层职责

| 层 | 文件 | 职责 | 不允许做的事 |
|---|---|---|---|
| 接入层 | `main.py` | 创建 app、注册路由、CORS、挂静态目录、SPA 回退 | 写业务逻辑 |
| 接口层 | `api.py` | 解析参数、调用分析/仓储、组装 JSON、抛 HTTP 错误 | 直接写 SQL、直接调 baostock |
| 分析层 | `analytics.py` | 纯函数：日线→月末、指标计算、月份区间 | 访问数据库/网络 |
| 仓储层 | `repo.py` | 所有表的增删改查、对方言做适配 | 计算指标、拼 HTTP |
| 模型层 | `db.py` | 引擎、表结构、`init_db()` | 业务查询 |
| 同步层 | `sync_service.py` | 水位线、抓取窗口、复权校验、任务状态、日志 | 被前端直接依赖内部细节 |
| 工具 | `seed.py` | 一次性导入 / 重置数据 | 参与运行时请求 |

> 规矩：**只有 `repo.py` 能碰数据库**。这样换 MySQL 时改动面被限制在一个文件里。

## 3. 请求链路

### 3.1 查询：行业详情

```
GET /api/industries/801770
  → api.industry_detail(code)
      → repo.list_industries()            取行业元数据（名称、成分数）
      → repo.list_stocks("801770")        取 5 只龙头（按 rank）
      → repo.prices_for([5 codes + 000300])  一次查出所有日线
      → analytics.group_by_code           按股票分组
      → analytics.to_monthly              每股聚合成月末序列（含 ret/norm）
      → analytics.metrics                 区间收益、年化、回撤、波动、最佳/最差月
  ← JSON { code, name, stockCount, leaders[5], benchmark, avgCumReturn, baseMonth }
```

**为什么要一次查完**：5 只龙头 + 基准共 6 只 × 约 700 个交易日 ≈ 4,200 行，SQLite 毫秒级；避免 N+1 查询。

### 3.2 增量同步

```
浏览器刷新
  → GET /api/data/version
      ← { lastTradeDate, expectedTradeDate, needsRefresh, lastSyncAt, syncing, rows }
  → needsRefresh == true 时：
      POST /api/sync
        → sync_service.start_sync("page")
            ├─ 已有任务在跑？→ 直接返回该 job（reused=true）
            └─ 否则建 job + 起后台线程，立即返回 { jobId }
      GET /api/sync/{jobId}（前端每 1.5s 轮询）
            ← { status: running, done, total, addedRows, rebuilt }
  → status == done → 前端 refreshKey++，重新拉取当前页面数据
```

后台线程内部：

```
_run(job)
  ├─ baostock.login()
  ├─ codes = 155 只龙头 + 000300
  ├─ global_last = MAX(trade_date)
  ├─ window_start = global_last - 10 天（重叠窗口，用于校验复权）
  ├─ for code in codes:
  │    ├─ rows = baostock 日线 [sym_last-10d, 今天]，adjustflag=2（指数 3）
  │    ├─ 找「同月份重叠收盘价」：db_close vs fetched_close
  │    ├─ 偏差 > 0.5% → 重抓全历史 + repo.replace_symbol（计入 rebuilt）
  │    └─ 否则 → 只插入 trade_date > sym_last 的新行（repo.upsert_prices）
  ├─ repo.set_state(last_trade_date / last_sync_at / last_sync_status)
  └─ repo.update_log(status=ok/failed, added_rows, rebuilt, message)
```

## 4. 并发模型

| 项 | 方案 | 理由 |
|---|---|---|
| Web 服务 | uvicorn 单进程、默认线程池 | 数据量小、无 CPU 密集任务 |
| 同步任务 | `threading.Thread` + `threading.Lock` | baostock 是阻塞 socket，放线程里不堵请求；锁保证单飞 |
| 任务状态 | 进程内字典 `_JOBS`（保留最近 20 个） | 无需 Redis；重启后丢失可接受（`sync_log` 已落库） |
| 数据库 | 同步线程与请求线程共用引擎 | SQLite 用 `check_same_thread=False`；写入是短事务 |
| 失败隔离 | 单只股票失败只记 message，不中断整体 | 155 只里个别停牌/退市不应拖垮同步 |

**为什么不用 asyncio + httpx**：数据源是 baostock 的私有 socket 协议，只有同步客户端；用线程更简单可靠。

## 5. 前端结构

```
main.tsx
  └─ App.tsx
       ├─ 路由：hash（#/ 与 #/industry/{code}?norm=1）
       ├─ 全局状态：version（水位线）、syncing、syncMsg、refreshKey
       ├─ 自动同步：needsRefresh 且本会话未同步过 → runSync('page')
       ├─ 页面：Overview | Industry
       └─ Footer：数据来源与免责声明

pages/Overview.tsx      KPI 4 卡 + OverviewBar（柱状图，带沪深300 markLine）+ 31 张行业卡
pages/Industry.tsx      模式切换（价格/归一化）+ LineChart + 指标表
components/LineChart.tsx   ECharts 折线封装：5 只龙头 + 可选基准；resize 监听；点击回调
components/OverviewBar.tsx ECharts 柱状封装：龙头 vs 前五等权；点击下钻
api.ts                  全部 fetch 封装（唯一网络出口）
types.ts                与后端响应对应的 TS 类型
```

设计取舍：

- **不用 react-router**：两个页面、hash 路由足够，减少依赖。
- **不用状态库**：页面级 `useState` + `refreshKey` 触发重取，避免过度设计。
- **ECharts 直接封装**：不引 `echarts-for-react`，少一层依赖，便于控制 `notMerge` 与 dispose。
- **绝对价格模式不叠加沪深300**：量级差 3~5 倍会把个股压成一条线（已踩过）。

## 6. 存储与可迁移性

- 表定义集中在 `db.py`，`metadata.create_all()` 建表；SQLite 与 MySQL 共用。
- 唯一方言差异在 `repo.upsert_prices`：
  - SQLite：`INSERT ... ON CONFLICT(code, trade_date) DO UPDATE`
  - MySQL：`INSERT ... ON DUPLICATE KEY UPDATE`
- 切换方式：改 `ASTOCK_DATABASE_URL`，装 `pymysql`，跑一次 `python -m app.seed`（或迁移脚本）。
- 未引入 Alembic：当前 5 张表、单人维护，`create_all` 够用；若开始改字段，建议引入（见 07）。

## 7. 部署形态

| 形态 | 端口 | 启动 | 适用 |
|---|---|---|---|
| 生产（本地） | 3999 | `start.sh` / `python run.py` | 日常使用，单端口 |
| 开发 | 3999 + 5173 | `python run.py --reload` + `npm run dev` | 改前端热更新 |
| 仅后端 | 3999 | `python run.py` | 调 API / 接第三方 |

服务只绑定 `127.0.0.1`；若要局域网访问，需显式改 `ASTOCK_HOST` 并自担风险（无 HTTPS、无强鉴权）。

## 8. 安全边界

| 面 | 现状 | 说明 |
|---|---|---|
| 网络 | 仅回环地址 | 不暴露公网 |
| 维护接口 | `X-Admin-Token` 固定 token | 默认 `local-dev-token`，可在 `.env` 改 |
| 查询接口 | 无鉴权 | 只读且本地，可接受 |
| SQL 注入 | SQLAlchemy 参数化 | 无字符串拼接 SQL |
| 依赖 | vendor 目录离线 | 无运行时联网安装 |
| 数据源 | 只读 | 不向上游写任何数据 |

## 9. 关键架构决策（摘要，详见 08）

1. Python FastAPI 而非 Node：复用 baostock 与既有数据管道。
2. SQLite 而非 JSON：SQL 语义、事务、索引，迁移 MySQL 成本最低。
3. 存前复权价 + 重叠校验重建，而非存不复权价 + 因子表：实现成本低，覆盖 99% 场景。
4. 同步走「单飞 + 异步 job + 轮询」：baostock 慢，不能阻塞请求。
5. 单端口 3999 托管前端：本地使用只要记一个地址。
