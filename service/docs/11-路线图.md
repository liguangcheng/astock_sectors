## 2. 下一版本 v0.2.3 · 同步稳定性（当前迭代）

**目标**：把「刷新页面等 5 分钟、上游异常时卡死、任务状态丢失」解决到「≤60 秒、可观测、可恢复」。

- [x] **残留日志自愈**：启动时把 `running` 日志自动标记 `failed`（2026-11-17 已上线并验证）
- [ ] **性能**：156 只串行约 318s → 目标 ≤60s
  - 复用 baostock 连接、合并查询窗口（一次取多日）
  - 受控并发（3~4 线程 + 限速 + 失败重试），避免触发上游限流
  - 只抓「自上次同步以来」的窗口，减少返回体积
- [ ] **总超时与熔断**（2026-11-17 上游超时事件后新增，P0）
  - 单次任务总时长上限（建议 10 分钟），超时自动中止并标记 `timeout`
  - 连续 N 只（建议 5 只）超时/失败即熔断，停止任务并提示「上游不可用」
  - 同步前做一次轻量探活（例如拉取 1 只股票最近 1 天），失败直接返回，不进 156 只循环
- [ ] **手动取消**：`POST /api/sync/{jobId}/cancel` 或超时中止，前端可点
- [ ] **健壮性**
  - 单只失败重试 2 次；失败清单写入 `sync_log.message`（JSON 列表，而非只留最后一条）
  - 全局限流与超时；连续失败提前终止
- [ ] **任务持久化**
  - 新增 `sync_job` 表（id/status/trigger/started/finished/added/rebuilt/error），替换内存 `_JOBS`
- [ ] **前端体验**
  - 同步进度显示 `done/total` + 已用时 + 预计剩余
  - 失败时给出可操作提示（重试按钮/查看日志）
- [ ] **可观测**
  - `sync_log` 增加 `duration_ms` 与 `failures` 字段

**验收**：

1. 正常增量（1 个交易日）≤60s；全量（首启）≤3min。
2. `rebuilt` 在无分红日必须为 0（2026-11-16 已验证规则）。
3. 同步中重启服务：重启后 `/api/data/version` 不显示 `syncing`，`sync_log` 无 `running`。
4. 上游不可用时：≤1 分钟内返回明确失败（熔断），而不是挂 10 分钟。
5. 失败时 `sync_log` 能列出具体股票与原因。

**依赖**：无。**风险**：baostock 并发限制未知，需小步试。

## 3. v0.3.0 · 数据维护页（P5）

**目标**：不碰命令行即可完成日常维护。

- [ ] `#/admin` 三个 Tab：龙头维护 / 同步中心 / 数据体检
- [ ] 龙头表格：行业下拉 → 5 行可编辑（权重、排序、是否龙头），保存调 `PUT /api/admin/stocks/{code}`

**验收**：改权重 → 刷新页面看到排名变化 → 触发同步 → 看到日志与耗时；全程不使用命令行。

## 4. v0.3.1 · MySQL 切换（P6）

**目标**：同一页面在 SQLite 与 MySQL 下数字完全一致，切换只改环境变量。

- [ ] 确认虚拟化并安装 Docker（或 MySQL 8.4 ZIP），映射 3307
- [ ] `python vendor_backend2.py pymysql`
- [ ] `ASTOCK_DATABASE_URL` 指向 MySQL，`python -m app.seed`
- [ ] 双库比对：行数 / 抽样价 / 页面指标（脚本化）
- [ ] `migrate_sqlite_to_mysql.py`（逐表读取 → 批量写入 → 校验）
- [ ] 决定长期形态（SQLite or MySQL），写入 `08-决策记录.md`
- [ ] 补 `utf8mb4`、`DOUBLE` 精度、外键建表顺序的验证

**验收**：`SELECT COUNT(*)` 与 SQLite 当前值一致；`/api/industries/801120` 的 `avgCumReturn` 一致。

## 8. 优先级与准入规则

| 优先级 | 含义 | 例子 |
|---|---|---|
| P0 | 影响正确性或可用性，必须立刻做 | 同步误判、任务卡死 |
| P1 | 明显影响日常使用 | 同步 5 分钟、维护靠命令行 |
| P2 | 提升效率/体验 | 图表交互、导出增强 |
| P3 | 锦上添花 | 移动端、主题 |

**进入版本的条件**：有明确验收标准 + 依赖已就绪 + 预估 ≤3 人日（超过则拆分）。

**版本发布条件**：验收项全部通过；`10-当前状态.md` 已更新；`09-变更日志.md` 已记录；`_check_docs.py` 通过。
